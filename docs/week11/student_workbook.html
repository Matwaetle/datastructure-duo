이론 정리 · 배경 지식
  • 탐색(순회)이란: 그래프의 한 노드에서 출발해, 간선으로 이어진 이웃으로 한 걸음씩 나아가며 노드를 살펴보는 일이에요. 길 찾기, 몇 단계 만에 닿는지 세기, 이어진 덩어리 세기가 모두 이 일이에요. 노드 하나를 살펴보는 것을 방문이라고 해요. 오늘은 “어느 이웃을 어떤 순서로 방문할까”를 직접 알아내요.
  • 그래프와 이웃: 점(노드)과 선(간선)으로 이루어져요. 파이썬에서는 딕셔너리에 노드마다 이웃 목록을 적어요(10주차). 한 걸음에 갈 수 있는 노드들이 그 노드의 이웃이에요.
  • 2차원 격자: 미로나 지도는 문자열 목록으로 나타내요. 한 칸은 grid[행][열]로 읽어요. 위·아래·왼쪽·오른쪽 네 칸이 이웃이에요. 이동량을 (행 변화, 열 변화) 쌍의 목록으로 적어 두고 반복해요. 가장자리 칸은 이웃이 격자 밖에 있을 수 있어서 범위 검사가 필요해요.
  • 방문 기록: 이미 본 노드를 적어 두는 곳이에요. 집합(set)은 “들어 있는가” 검사 x in seen이 빨라요.
  • 컨테이너: 앞으로 볼 노드를 잠시 담아 두는 자료구조예요. 5주차에 배운 두 가지를 떠올려 봐요. 스택은 가장 나중에 넣은 것을 먼저 꺼내요. 큐는 가장 먼저 넣은 것을 먼저 꺼내요. 파이썬에서 스택은 list의 append와 pop()으로, 큐는 collections.deque의 append와 popleft()로 써요.
  • 재귀와 호출 스택: 함수가 자기 자신을 부르면, 부른 함수가 끝날 때까지 호출 기록이 쌓였다가 거꾸로 사라져요(8주차). 이 기록이 쌓이는 곳이 Call Stack이에요.
  • 시간복잡도 읽는 법: 입력 크기에 따라 작업 횟수가 어떻게 늘어나는지를 O(…)로 적어요. O(N)은 “개수 N에 비례해 늘어난다”, O(1)은 “개수와 상관없이 한 번에” 걸린다는 뜻이에요. 그래프의 노드 수는 V, 간선 수는 E로 적어요. 격자의 행·열 수는 R, C로 적어요.

작은 예 1 · 컨테이너 연산 (활동 데이터와 다른 값이에요.)

from collections import deque
box = deque(["x", "y"])
box.append("z")
print(box)               # deque(['x', 'y', 'z'])
print(box.popleft(), box)  # x deque(['y', 'z'])
print(box.pop(), box)      # z deque(['y'])
print(len(box) == 0)       # False

작은 예 2 · 그래프 딕셔너리와 방문 기록

g = {"P": ["Q", "R"], "Q": ["P"], "R": ["P", "S"], "S": ["R"]}
print(g["R"])                  # ['P', 'S']
for nb in g["R"]:
    print("R의 이웃:", nb)     # R의 이웃: P / R의 이웃: S
seen = set()
seen.add("P")
print("P" in seen, "Q" in seen)  # True False

작은 예 3 · 격자의 네 이웃과 범위 검사

grid = ["..#",
        "#.."]
R, C = len(grid), len(grid[0])
print(R, C, grid[1][2])        # 2 3 .
DIRS = [(-1, 0), (1, 0), (0, -1), (0, 1)]
r, c = 1, 1
for dr, dc in DIRS:
    nr, nc = r + dr, c + dc
    if 0 <= nr < R and 0 <= nc < C:
        print((nr, nc), grid[nr][nc])
    else:
        print((nr, nc), "격자 밖")   # (0, 1) . / (2, 1) 격자 밖 / (1, 0) # / (1, 2) .

A1 · 이웃으로 계속 나아가기: 어느 이웃부터 갈까1차시 · 7분 · 개인

미로에서 출구 찾기, 소문이 몇 단계에 닿는지 세기, 위성지도에서 땅 덩어리 세기. 셋 모두 이웃으로 계속 나아가는 문제예요.

작은 미로 보기

입구에서 출구까지 가는 길을 찾아요. 길이 셋 이상 만나는 곳이 갈림길이에요.

입구 ─ P ─ Q ─ 출구
       │
       R  (막힌 길)

그림에서 갈림길은 어디일까?

P에서 입구, Q, R 세 길이 만나요.

갈림길에서 고르기

P에서 R로 들어갔는데 막다른 길이었다고 해 봐요. 내 말로 써 봐요.

갈림길에서 어느 쪽으로 갈까요? 막히면 어떻게 할까요?

지나온 곳을 또 가면

X, Y, Z 세 사람은 서로 모두 친구예요. 소문이 X에서 Y로, Y에서 Z로 갔어요.

가 본 곳을 적어 두지 않고 Z에서 다시 X로, Y로… 계속 가면 어떻게 될까요?

같은 곳을 또 가니까 언제 끝날지 알 수 없어요.

소문은 몇 단계

소문이 A에서 B로, B에서 C로 퍼졌어요. 시작한 A는 0단계예요.

C에게 소문은 몇 단계 만에 닿았을까요?

A-B, B-C로 두 번 전해졌어요. 단계는 지나온 친구 관계(간선)의 수예요.

내 방법 한 문장 쓰기

앞의 작은 미로를 떠올려 봐요. 지금 있는 곳에서 다음에 어디를 볼지 정하는 내 방법을 한 문장으로 써요. BFS·DFS 같은 이름은 몰라도 돼요.

미로에서 다음에 어디를 볼지 정하는 내 방법

(선택) 이 방법이 곤란해질 것 같은 곳

여기까지 미로에서 쓸 내 방법을 한 문장으로 썼어요. A2에서는 두 가지 규칙을 손으로 따라가며 확인해요.

다 쓰고 나서 열어 봐요 · 세 사례의 공통점과 말뜻
  • 세 사례는 모두 “지금 있는 곳에서 이웃으로 한 걸음씩 나아가는” 문제예요. 그래서 갈림길에서 어느 이웃을 먼저 볼지 정하는 규칙이 필요해요.
  • “몇 단계”는 소문이 전해진 횟수예요. 곧 시작한 사람에서 그 사람까지 지나는 친구 관계(간선)의 수예요.
  • 이미 지나온 곳을 또 가면 같은 곳을 빙빙 돌아 끝나지 않거나 시간을 낭비해요. 그래서 가 본 곳을 적어 둘 곳이 필요해요.
  • 어느 이웃부터 가느냐에 따라 지나는 길과 순서가 달라져요. 이 차이를 A2부터 손으로 따라가며 확인해요.

A2 · 컨테이너 두 가지로 손 탐색하기1차시 · 14분 · 개인

컨테이너에서 꺼내는 자리만 바꾸면 방문 순서가 달라질까요? 작은 그래프 X로 규칙을 보고, G1에서 두 번 따라 해 봐요.

작은 그래프 X 보기

컨테이너는 앞으로 볼 노드를 담아 두는 곳이에요. 스택은 맨 위(오른쪽 끝)에서 꺼내고, 큐는 맨 앞(왼쪽 끝)에서 꺼내요. 먼저 시작 노드를 넣어요. 그다음 ‘꺼낸다 → 방문한다 → 안 가 본 이웃을 목록 순서로 넣는다’를 컨테이너가 빌 때까지 되풀이해요. 방문한 차례가 방문 순서예요.

X: [Y, Z]   Y: [X]   Z: [X]       스택 규칙, 시작 X

시작        컨테이너 [X]
단계 1      꺼냄 X (방문)  → 컨테이너 [Y, Z]
단계 2      꺼냄 Z (방문)  → 컨테이너 [Y]
단계 3      꺼냄 Y (방문)  → 컨테이너 [ ]
방문 순서   X, Z, Y

같은 X에서 큐 규칙이라면, 단계 1 다음에 꺼내는 노드는?

큐는 맨 앞의 Y를 꺼내요. 스택은 맨 위의 Z를 꺼냈어요.

큐 규칙으로 X를 돌면 방문 순서는?

X, Y, Z예요. 스택 규칙의 X, Z, Y와 둘째 노드가 달라요.

스택 규칙으로 G1 돌기

G1은 노드 A~F, 간선 (A,B) (A,C) (B,D) (C,D) (D,E)예요. F는 외톨이예요. 시작 상태는 컨테이너 [A], 방문 기록은 비어 있어요. 표는 6단계까지예요. 일찍 끝나면 남는 칸은 비워 둬요.

A ─ B
│   │
C ─ D ─ E        F

A: [B, C]   B: [A, D]   C: [A, D]   D: [B, C, E]   E: [D]

이웃을 넣을지는 방문 기록만 보고 정해요. 컨테이너 안에 이미 있어도 방문 전이면 넣어요. 손으로 할 때 헷갈리지 않게 만든 단순한 규칙이에요. 코드는 다르게 할 수도 있어요(2차시).

  • 같은 노드(스택의 B, 큐의 D)가 컨테이너에 두 번 들어갈 수 있어요. 그래서 꺼낸 뒤 방문 기록을 확인해 버려야 같은 노드를 두 번 처리하지 않아요.
  • 스택은 D를 방문할 때 B, E를 목록 순서로 넣어요. 그러면 맨 위가 E라서 E가 먼저 나와요.
  • 같은 곳은 규칙 1~4단계의 틀(넣고, 꺼내고, 방문 기록에 쓰고, 이웃을 넣고, 반복)이에요. 다른 곳은 꺼내는 쪽(맨 위 대 맨 앞)이에요.
  • F는 어느 노드와도 간선이 없어요. 그래서 A에서 이웃을 따라가도 닿지 않아요. 시작 노드에서 닿는 노드만 방문돼요. F가 방문되려면 F와 이어진 간선이 있어야 해요.

A3 · 재귀로 돌아보기: 호출이 쌓이는 모습1차시 · 13분 · 개인

재귀 함수도 노드를 깊이 따라 들어가요. 호출이 쌓이는 모습을 작은 그래프 P에서 먼저 봐요.

호출이 쌓이는 모습

함수가 시작될 때를 enter, 끝나 돌아올 때를 exit라고 해요. 호출은 Call Stack에 쌓이고, 끝나면 맨 위부터 사라져요. 이 스택은 파이썬이 호출마다 자동으로 관리해요. Call Stack 칸은 아래에서 위로 [P, Q]처럼 써요.

P: [Q]   Q: [P, R]   R: [Q]     dfs(P)를 따라 간 모습

순서  사건      Call Stack(아래부터)
 1   enter P   [P]
 2   enter Q   [P, Q]
 3   enter R   [P, Q, R]
 4   exit R    [P, Q]
 5   exit Q    [P]
 6   exit P    [ ]

순서 5에서 exit Q를 한 직후, Call Stack의 맨 위는?

Q가 끝나 사라지면 아래에 있던 P가 맨 위가 돼요.

이 Call Stack은 누가 만들어 줄까요?

재귀 호출이 있으면 파이썬이 알아서 쌓고 치워요.

G1을 재귀로 따라가기

시작 A에서 아래 의사코드를 따라가요. 표는 10줄이 모두 필요해요. 사건과 Call Stack 두 가지만 써요.

A ─ B
│   │
C ─ D ─ E        F

A: [B, C]   B: [A, D]   C: [A, D]   D: [B, C, E]   E: [D]
def dfs(u):          # 의사코드
    visited에 u 추가, order에 u 기록
    for 이웃 v in (u의 이웃 목록 순서):
        if v가 visited에 없으면:
            dfs(v)

이웃 목록을 앞에서부터 보다가, 방문하지 않은 이웃을 만나면 그 자리에서 바로 호출해요. 호출이 끝나면 돌아와서 다음 이웃을 이어서 봐요.

8주차 트리 순회는 visited 없이도 끝났어요. 그래프 순회에는 왜 visited가 필요할까요? 트리와 그래프의 구조 차이로 써요. (사이클: 돌아서 제자리로 오는 길)

A4 · 두 갈래 길 그래프 H에서 세 방식 비교1차시 · 14분 · 개인

시작과 목표가 같아도 규칙과 이웃 순서에 따라 처음 닿는 길이 달라질까요? 작은 그래프 W부터 봐요.

작은 그래프 W 보기

W는 노드 3개이고, S의 이웃 목록은 [A, B]예요. 세 방식으로 S에서 돌면 방문 순서는 이래요.

A ─ S ─ B        S: [A, B]   A: [S]   B: [S]

큐 규칙   : S, A, B
스택 규칙 : S, B, A
재귀      : S, ?, ?

재귀는 S 다음에 어느 노드를 방문할까요?

재귀는 목록의 첫 이웃 A로 바로 들어가요. 스택 규칙은 A, B를 모두 넣고 마지막에 넣은 B를 먼저 꺼냈어요.

경로 되짚기 보기

큐 규칙으로 돌면서, 노드를 넣을 때마다 ‘누가 넣었는지’를 적어 둬요. 목표에 닿으면 그 기록을 거꾸로 따라 S까지 가요. 그게 경로예요.

    A ─ T        S: [A, B]   A: [S, T]
   /             B: [S]      T: [A]
 S
   \
    B

넣은 기록   A ← S,  B ← S,  T ← A
T에서 거꾸로   T ← A ← S   →   경로 S-A-T (간선 2개)

이 경로 S-A-T의 간선 수는?

노드가 3개니까 간선은 2개예요.

H에서 세 방식 돌리기

H는 노드 6개, 간선 6개(무방향) (S,A) (S,B) (A,C) (C,D) (D,T) (B,T)예요. 시작은 S, 목표는 T이고, 이웃 순서는 목록 순서예요. 큐 규칙, 스택 규칙, 재귀로 돌려서 표를 채워 봐요.

        ┌─ A ── C ── D ─┐
   S ───┤                T
        └─ B ───────────┘

S: [A, B]   A: [S, C]   B: [S, T]   C: [A, D]   D: [C, T]   T: [D, B]

T에 처음 도착한 경로는 T가 처음 방문된 때의 경로예요. 큐·스택은 위의 되짚기로 찾아요. 재귀는 그때의 Call Stack을 읽어요. S-…-T로 써요.

두 표를 보고 ‘무엇이 흔들리고 무엇이 안 흔들리는가’에 대한 가설을 세 줄로 써요. 가설은 아직 확인하지 않은 내 생각이에요. 세 줄은 서로 다른 내용으로 써요.
