사용법#how

  • 편집기에는 필요한 코드가 미리 들어 있다. ____1____ 같은 자리를 채우고 [▶ 실행]을 누른다.
  • [✔ 점검]은 내 코드가 맞는지 확인해 준다. [처음 코드로]는 편집기를 처음 상태로 되돌린다.
  • 편집기에 쓴 내용은 자동으로 보관된다. 다 했으면 위의 [저장(JSON)]으로 제출 파일을 만든다.
단축키와 오류가 날 때
  • Ctrl(⌘)+Enter는 실행, Tab은 들여쓰기, Shift+Tab은 내어쓰기이다.
  • 오류가 나면 맨 아래 줄부터 읽는다. NameError: name '____1____' is not defined는 그 번호의 자리가 아직 비어 있다는 뜻이다.
  • 같은 쪽의 편집기는 파이썬 환경을 함께 쓴다. 위 편집기에서 실행한 함수를 아래 연습 편집기에서 부를 수 있다.
  • 실행이 15초를 넘기면 멈춘다. 끝나지 않는 반복이 있는지 확인한다.

A7 · 세 가지 방식으로 구하고 횟수 재기11분 · 개인

같은 피보나치 값을 세 가지 방식으로 구해 보자. 방식마다 일한 횟수는 어떻게 다를까?

호출을 그림으로 보기

fib(4)를 정의대로 구하면 fib(3)과 fib(2)를 부르고, 그 둘이 또 작은 값을 부른다. 부른 곳을 모두 그렸다.

fib(4)
├─ fib(3)
│   ├─ fib(2)
│   │   ├─ fib(1)
│   │   └─ fib(0)
│   └─ fib(1)
└─ fib(2)
    ├─ fib(1)
    └─ fib(0)

그림에서 fib(2)는 몇 번 나올까?

같은 fib(2)를 두 번 푼다. 호출은 모두 9번이다.

한 번 푼 답을 적어 두면

fib(4)
├─ fib(3)
│   ├─ fib(2)
│   │   ├─ fib(1)
│   │   └─ fib(0)

fib_memo 채우기

fib_memo(n, memo)의 ①②를 채우자. 호출하는 쪽이 빈 사전 {}을 넘기고, 함수는 n번째 피보나치 수를 돌려준다.

①은 “n의 답이 적혀 있는가”를 묻는 조건이다. ②는 fib_naive의 마지막 줄과 비슷하되 memo를 함께 넘긴다.

실행하면 NameError: ____3____가 나오는 것이 정상이다. ③은 다음 걸음에서 채운다. 아래에서 fib_memo(4)를 불러 호출 수가 7인지 보자.

fib_tab 채우기

fib_tab은 작은 값부터 표 dp를 채운다. dp[i]는 fib(i)의 값이다.

i       0  1  2  3  4  5
dp[i]   0  1  1  2  3  5

dp[4]는 어느 두 칸의 합일까?

dp[3] + dp[2] = 2 + 1 = 3이다. ③도 같은 모양이다.

활동지 2부 A7의 표에 n = 20, 30의 예측을 먼저 쓴다. ③을 채워 실행하면 횟수 두 줄이 나온다(몇 초 걸릴 수 있다). 아래에서 칸을 채운 횟수도 보자.
