  • 상태 dp[r][c]는 (0, 0)에서 (r, c)까지 오른쪽·아래로만 가는 경로의 수이다.
  • 전이 막힌 칸이면 0이고, 아니면 위 칸 + 왼쪽 칸이다(격자 안에 있는 칸만 더한다).

  • 계산 순서 행 우선(위에서 아래, 왼쪽에서 오른쪽)이다. 참조하는 위 칸과 왼쪽 칸이 먼저 채워지는 순서이다.

  • 0행은 시작 1에서 왼쪽 칸만 이어 [1, 1, 1, 1, 1]이다. 1행은 막힌 (1, 1), (1, 3)이 0이고 (1, 2) = 위 1 + 왼쪽 0 = 1이다. 2행은 (2, 2) = 1 + 1 = 2, (2, 4) = 위 1 + 왼쪽 2 = 3이다. 3행은 막힌 (3, 0), (3, 2)가 0이고 (3, 3) = 2 + 0 = 2이다.
  • 도착 (3, 4) = 위 (2, 4)의 3 + 왼쪽 (3, 3)의 2 = 5이므로 grid_paths(GRID)는 5이다.
  • ⑫(막힌 칸을 0으로 두는 줄)는 그 칸이 이미 0이라 있어도 없어도 같은 값이 나온다. “막힌 칸은 0”이라는 의도를 코드에 적어 두는 줄이다.

정리 문장과 대조하기

정제 문장을 쓴 뒤에만 아래 상자를 연다. G1~G4와 내 문장의 같은 점과 다른 점을 찾는다. 정리 문장에 맞추려고 고치지 않고 빠진 것을 찾는다.

A13 정제 문장과 기준표를 쓴 뒤에만 연다 · 일반화 정리 G1~G4와 채점기준표
  • G1 같은 부분 문제가 반복해서 나타나는 문제는 한 번 계산한 결과를 기억해 두면 비용이 “호출의 수”가 아니라 “서로 다른 부분 문제의 수”로 줄어 지수에서 다항으로 떨어지지만, 이 이득은 부분 문제가 겹치고 그 수가 작을 때만 생기며 겹치지 않는 분할(병합 정렬)에는 기억해도 얻는 것이 없다.
  • G2 DP는 상태 정의, 전이, 초기값, 계산 순서의 네 가지를 정하는 설계이며, 메모이제이션(하향식)과 타뷸레이션(상향식)은 같은 상태 공간을 다른 방향에서 채우는 방법이라 결과는 같지만 재귀 깊이·필요한 상태만 계산하는지 여부·계산 순서를 직접 정해야 하는 부담에서 갈리고, 불가능한 상태를 INF 같은 값으로 구별해 두지 않으면 최솟값이 오염된다.
  • G3 Greedy는 매 단계의 최선을 고르고 되돌리지 않아 DP보다 훨씬 빠르지만 지금의 최선이 전체의 최선임이 보장될 때만 최적이며, 같은 알고리즘이 어떤 동전 체계에서는 맞고 다른 체계에서는 틀리므로 Greedy는 증명하거나 반례를 찾아 검증해야 하고 반례 하나는 충분한 반증이 되지만 맞는 몇 개의 금액은 증명이 되지 못한다.
  • G4 알고리즘 설계 패러다임은 “부분 문제가 겹치는가, 선택을 되돌릴 일이 없는가”로 고른다. 부분 문제가 겹치고 최적 부분 구조가 있으면 DP, 선택이 이후 선택을 해치지 않음을 보일 수 있으면(활동 선택의 끝나는 시각 빠른 순 등) Greedy, 부분 문제가 서로 겹치지 않으면 분할 정복이며, 같은 종류 문제라도 선택 기준(끝나는 시각 대 시작 시각)이나 입력 구조(동전 체계)에 따라 Greedy의 정당성이 달라진다.
  • 겹침 대 비겹침(G1의 마지막 구절) fib(5)의 호출 트리 15개 노드에는 같은 n이 반복된다(fib(3) 2번, fib(2) 3번, fib(1) 5번, fib(0) 3번). 8개를 쪼개는 병합 정렬 호출 트리의 15개 구간은 모두 다르다. 앞의 것은 기억하면 줄어들고 뒤의 것은 기억해도 얻는 것이 없다.
  • 채점기준표 이제 rubric.html(실습 과제 채점기준표)을 연다. A14에서 서술을 다듬을 때 이 기준표를 본다.

내 문장에 “겹친다”, “저장한다”, “선택을 되돌리지 않는다” 중 빠진 것이 있는지, 문장에서 사례를 지워도 남는지 살펴보고 아래 대조 메모에 쓴다. G3의 “증명 또는 반례” 중 A9에서 내가 한 일이 어느 쪽인지도 생각해 본다.

  • 수업 중 활동(A1~A15)은 AI 없이 한다. 형성평가는 AI를 쓰지 않는 시험 상황이다. 위 3단계는 과제를 제출할 때 적용된다.
  • 제출할 JSON은 모두 5개(실습 코드 4개, 형성평가 1개)이다. 활동지는 제출하지 않는다.
이 활동지는 제출하지 않는다. A16에 쓴 내용은 이 브라우저에 자동으로 보관된다.
마지막 활동 A16을 마친 뒤 연다 · 용어, 일반화와 정리

A16까지 모두 쓴 뒤에 여는 상자이다. 아래 일반화를 A12에서 직접 쓴 내 문장과 견주어 본다.

용어와 표기

  • 메모이제이션(memoization): 위에서 아래로(큰 문제 → 작은 문제) 재귀로 풀면서 구한 답을 dict 등에 적어 두는 방식. 타뷸레이션(tabulation): 아래에서 위로(작은 문제부터) 반복문으로 표를 채우는 방식.
  • 최적 부분 구조: 문제의 최적해가 작은 문제의 최적해로 이루어지는 성질. 겹치는 부분 문제: 같은 작은 문제가 여러 번 나타나는 성질. 작은 문제들이 겹쳐야 저장해 다시 쓰는 일이 의미가 있다.
  • 반례(counterexample): 어떤 주장이 항상 맞지 않음을 보이는 단 하나의 예. 맞다는 것을 보이려면 예 몇 개로는 부족하지만, 틀렸다는 것은 반례 하나로 보일 수 있다.
  • DP의 일의 양은 대략 (상태의 수) × (한 상태를 구할 때 따지는 후보의 수)로 어림한다. 합 예제는 상태가 n+1개이고 상태마다 후보가 1개이다.

오늘의 일반화와 결론

  • Greedy의 계산 계산은 빠르지만 그 선택이 언제나 전체에서 가장 좋은지는 별도로 따져 봐야 한다.
  • 일반화 같은 작은 문제가 되풀이되면 그 답을 저장해 다시 쓰는 것만으로 일의 양이 크게 줄어든다(메모이제이션·타뷸레이션은 이를 구현하는 두 방향이다). 이때 상태 정의와 전이 규칙이 올바른지가 핵심이다.
  • Greedy와 DP의 차이 Greedy는 선택 하나를 정하고 되돌아보지 않으므로 빠르지만, 모든 경우에 최적이라는 보장이 없다. 보장이 없음은 반례 하나로 보일 수 있다. DP는 가능한 후보를 모두 따져 최적을 구한다.
  • 복잡도 겹치는 부분 문제를 그대로 재귀로 풀면 일의 양이 지수적으로 늘 수 있지만, 상태 수만큼만 계산하면 (상태 수) × (후보 수)로 줄어든다. 대신 상태를 저장할 메모리가 든다.

그 밖의 오개념

“DP는 항상 재귀이다”, “Greedy는 틀린 방법이다”, “예 몇 개가 맞으면 항상 맞다”는 A16 오개념 점검(문장 1·2·4)의 확인 상자에서 다룬다. 아래는 A16에서 다루지 않은 것이다.

  • “메모를 쓰면 호출이 한 번도 중복되지 않는다.” 호출은 일어나지만 저장된 답을 바로 돌려주므로 실제 계산은 한 번만 한다.
  • “DP 표의 값은 동전 종류이다.” 표의 값은 문제가 구하는 양(예: 개수)이고, 어떤 선택으로 얻었는지는 따로 기록해야 알 수 있다.
