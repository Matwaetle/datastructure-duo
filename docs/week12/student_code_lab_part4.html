A11 · 정렬 코드와 비교 횟수 측정12분 · 개인

A4에서 손으로 해 본 병합 정렬과 퀵 정렬을 코드로 옮겨요. 그리고 비교 횟수를 직접 세어 봐요.

합칠 때 비교 세기

병합 정렬은 정렬된 두 리스트를 하나로 합쳐요. 앞에서 한 원소씩 비교해서 작은 쪽을 꺼내요. 이렇게 한 번 비교하는 게 비교 한 번이에요.

l = [1, 4]   r = [2, 3]   out = []

1 과 2 비교 → 1이 작다     out = [1]
4 와 2 비교 → 2가 작다     out = [1, 2]
4 와 3 비교 → 3이 작다     out = [1, 2, 3]
r이 비었다 → 남은 4는 비교 없이 붙인다     out = [1, 2, 3, 4]

l = [1, 2], r = [3, 4]를 합칠 때 비교는 모두 몇 번일까요?

1과 3, 2와 3을 비교한 두 번이에요. l이 비면 3과 4는 비교 없이 붙어요.

피벗으로 나누기

퀵 정렬은 첫 원소를 피벗으로 삼아요. 나머지 원소가 피벗보다 작으면 small에, 아니면 big에 담아요. 같은 값은 big으로 보내요. 나머지 원소 하나를 피벗과 비교하는 게 비교 한 번이에요.

[4, 2, 6, 4]   피벗 4, 나머지 [2, 6, 4]

2 < 4 ? 예      → small
6 < 4 ? 아니오  → big
4 < 4 ? 아니오  → big     (같은 값은 big)

small = [2]   big = [6, 4]   비교 3번

[3, 1, 2]에서 피벗 3을 고르면 big에 담기는 원소는 몇 개일까요?

1과 2가 모두 3보다 작아서 small에 들어가요. big은 비어 있어요.

cnt 칸과 리스트 자르기

비교 횟수는 숫자 하나를 담은 리스트 cnt에 세요. 함수 안에서 cnt[0] += 1을 하면 밖의 칸도 늘어나요. 리스트를 자르는 l[i:]와 이어 붙이는 +도 함께 써 봐요.

l = [1, 4, 6], i = 1일 때 l[i:]는 무엇일까요?

l[i:]는 i번째부터 끝까지예요. 출력의 둘째 줄과 같아요.

merge_sort 채우기

아래 편집기에 두 정렬의 뼈대가 들어 있어요. 먼저 merge_sort의 ⑫⑬⑭를 채워요. ⑫는 더 쪼갤 수 없을 때의 조건이에요. ⑬은 같으면 왼쪽을 먼저 꺼내는 조건이에요. ⑭는 남은 것을 이어 붙인 결과예요.

NameError: name '____13____' is not defined가 나오면 그 번호 자리가 아직 비어 있다는 뜻이에요.

[▶ 실행]을 눌러도 출력은 없어요. 아래 편집기로 merge_sort를 불러 확인해 봐요.

quick_sort 채우기

같은 편집기에서 quick_sort의 ⑮⑯⑰을 채워요. ⑮는 피벗이에요. ⑯은 small에 넣는 조건이에요. ⑰은 small 정렬 결과, 피벗, big 정렬 결과를 이어 붙인 리스트예요.

(small if ⑯ else big).append(x)는 조건이 참이면 small에, 아니면 big에 x를 넣어요.

채운 뒤 위 편집기를 실행하고, 아래 편집기로 확인해요.

가까운 값 찾기 보기

정렬된 리스트에서 x와 가장 가까운 원소를 찾아요. 거리가 같으면 작은 값을 골라요.

S = [10, 20, 40]

x = 26 → 20과의 거리 6, 40과의 거리 14   → 가장 가까운 값은 20

x = 30이면 가장 가까운 값은 무엇일까요?

20과 40이 모두 거리 10이에요. 같으면 작은 값을 고르니까 20이에요.

삽입 자리 찍어 보기

bisect_left(S, x)는 x가 들어갈 자리 i를 돌려줘요. x를 여러 값으로 바꿔 i를 찍어 봐요. i 둘레의 어느 값들을 비교하면 가장 가까운 값을 찾을 수 있을지 생각해 봐요.

x = 26일 때 i는 얼마일까요? (자리 번호는 0부터 세요)

세 함수 한 칸에 모으기

아래 편집기가 제출하는 칸이에요. 실습 코드 2부 A9의 [내 코드 · A9 (count_equal, count_in_range 작성)] 칸에서 두 함수를 복사해 1) 자리에 붙여요. closest_value는 2) 자리에 써요. 다 쓰면 [▶ 실행]을 눌러요(출력은 없어요).

  • closest_value(a, x): x와 가장 가까운 원소를 돌려줘요. 거리가 같으면 작은 값, 빈 리스트이면 None이에요.
  • 세 함수는 bisect로 O(log N)에 구해요. 입력 리스트를 바꾸거나 다시 정렬하지 않아요. 입력은 오름차순이에요.

NameError가 나오면 A9의 두 함수를 편집기 맨 위에 붙였는지, 칸 전체를 실행했는지 봐요.

밧줄 자르기 보기 (선택)

밧줄을 모두 같은 길이 L로 자르면, 조각 수는 밧줄마다 r // L을 구해 더한 값이에요. 조각이 k개 이상이 되는 가장 긴 L을 구하는 선택 문제예요. 채점하지 않아요.

ropes = [10, 7]   L = 3  →  10 // 3 = 3,  7 // 3 = 2  →  조각 5개

ropes = [10, 7]을 L = 2로 자르면 조각은 몇 개일까요?

10 // 2 = 5와 7 // 2 = 3을 더한 8개예요.

범위 줄이기 (선택)

후보 길이의 범위 [lo, hi]를 절반씩 줄여 가장 긴 L을 찾아요. ⑱은 mid 길이로 잘랐을 때 조각이 충분한지 묻는 조건이에요. ⑲는 그렇지 않을 때 hi의 새 값이에요. 채운 뒤 [▶ 실행]과 [✔ 점검]을 눌러요.

점검이 낸 가장 긴 L과 호출 횟수는 활동지 3부 A14의 [코드 결과] 칸에 써요.

다 하고 나서 열어 봐요 · TA 점검 기대값

TA = [2, 2, 2, 6, 6, 10, 14, 14, 14, 14, 18]에서 손으로 구한 값이에요. 점검 코드는 이 값을 쓰지 않고 하나씩 세어 비교해요. 그러니 이 값은 내 결과를 눈으로 맞춰 볼 때 써요.

함수호출 → 값
count_equal(TA, 2) → 3 · (TA, 6) → 2 · (TA, 14) → 4 · (TA, 18) → 1 · (TA, 8) → 0 · (TA, 0) → 0 · (TA, 99) → 0 · ([], x) → 0
count_in_range (양끝 포함)(TA, 3, 14) → 7 · (TA, 2, 2) → 3 · (TA, 6, 6) → 2 · (TA, 7, 9) → 0 · (TA, 0, 100) → 11 · (TA, 19, 30) → 0 · (TA, -5, 1) → 0 · (TA, 14, 6) → 0 · ([], lo, hi) → 0
closest_value (동률이면 작은 값)(TA, 0) → 2 · (TA, 2) → 2 · (TA, 4) → 2 · (TA, 8) → 6 · (TA, 12) → 10 · (TA, 16) → 14 · (TA, 20) → 18 · (TA, 99) → 18 · (TA, 6) → 6 · (TA, 10) → 10 · ([], x) → None

closest_value(TA, 4)는 2와 6이 같은 거리라서 작은 값 2예요. 입력 리스트를 정렬하거나 바꾸면 “입력 불변” 점검에서 걸려요.
