합칠 때 비교 세기

병합 정렬은 정렬된 두 리스트를 하나로 합친다. 앞에서 한 원소씩 견주어 작은 쪽을 꺼내는데, 이 견주기 한 번이 비교 한 번이다.

l = [1, 4]   r = [2, 3]   out = []

1 과 2 비교 → 1이 작다     out = [1]
4 와 2 비교 → 2가 작다     out = [1, 2]
4 와 3 비교 → 3이 작다     out = [1, 2, 3]
r이 비었다 → 남은 4는 비교 없이 붙인다     out = [1, 2, 3, 4]

l = [1, 2], r = [3, 4]를 합칠 때 비교는 모두 몇 번일까?

1과 3, 2와 3을 견준 두 번이다. l이 비면 3과 4는 비교 없이 붙는다.

피벗으로 나누기

퀵 정렬은 첫 원소를 피벗으로 삼는다. 나머지를 피벗보다 작으면 small에, 아니면 big에 담고, 같은 값은 big으로 보낸다. 나머지 원소와 피벗을 견주는 것이 비교 한 번이다.

[4, 2, 6, 4]   피벗 4, 나머지 [2, 6, 4]

2 < 4 ? 예      → small
6 < 4 ? 아니오  → big
4 < 4 ? 아니오  → big     (같은 값은 big)

small = [2]   big = [6, 4]   비교 3번

[3, 1, 2]에서 피벗 3을 고르면 big에 담기는 원소는 몇 개일까?

1과 2가 모두 3보다 작아 small에 들어간다. big은 비어 있다.

x = 30이면 가장 가까운 값은 무엇일까?

20과 40이 모두 거리 10이다. 같으면 작은 값이므로 20이다.

삽입 자리 찍어 보기

bisect_left(S, x)는 x가 들어갈 자리 i를 돌려준다. x를 여러 값으로 바꿔 i를 찍어 보자. i 둘레의 어느 값들을 견주면 가장 가까운 값을 찾을 수 있을지 생각해 본다.

x = 26일 때 i는 얼마일까? (자리 번호는 0부터 센다)

세 함수 한 칸에 모으기

아래 편집기가 제출하는 칸이다. 실습 코드 2부 A9의 [내 코드 · A9 (count_equal, count_in_range 작성)] 칸에서 두 함수를 복사해 1) 자리에 붙이고, closest_value를 2) 자리에 쓴다. 쓴 뒤 [▶ 실행]을 누른다(출력은 없다).

  • closest_value(a, x): x와 가장 가까운 원소를 돌려준다. 거리가 같으면 작은 값, 빈 리스트이면 None이다.
  • 세 함수는 bisect로 O(log N)에 구한다. 입력 리스트를 바꾸거나 다시 정렬하지 않는다. 입력은 오름차순이다.

NameError가 나오면 A9의 두 함수를 편집기 맨 위에 붙이고 칸 전체를 실행했는지 본다.

과제 점검하기

위 편집기의 [✔ 점검]은 새 입력 TA에서 count 두 함수를 본다. 값이 하나씩 센 값과 같은가, 입력이 그대로인가, 100만 개에 질의 10만 번이 약 1초 안쪽인가를 확인한다. 통과하면 A14 값 점검 통과와 큰 입력 점검 끝: …초가 나온다.

closest_value는 아래 편집기의 [✔ 점검]으로 확인한다. 먼저 위 편집기를 실행해 둔다.

점검 결과는 활동지 3부 A14의 점검표에 표시한다. 시간이 모자라면 closest_value 점검은 주간 과제에서 한다.

막히면 · 점검이 느리거나 실패할 때

점검이 느리거나 중단되면 100만 개를 하나씩 훑는 코드(list.count나 for 문)가 없는지 본다. 메시지의 r이 내 결과이고 v가 더 알맞은 값이면, 메시지의 x를 작은 리스트에 넣고 bisect_left가 준 i를 찍어 보자. i가 리스트의 맨 앞이거나 맨 뒤일 때 내 코드가 어디를 읽는지 본다. 활동지 2부 A9의 ‘어느 원소들만 보면 되는가’도 다시 읽는다.

복잡도 쓰기

쓰기 전에, 후보를 한 번에 절반씩 줄이면 몇 번 만에 다 없어지는지 세어 보자. N을 바꿔 가며 실행해도 좋다.

밧줄 자르기 보기 (선택)

밧줄을 모두 같은 길이 L로 자르면 조각 수는 밧줄마다 r // L의 합이다. 조각이 k개 이상이 되는 가장 긴 L을 구하는 선택 문제이고, 채점하지 않는다.

ropes = [10, 7]   L = 3  →  10 // 3 = 3,  7 // 3 = 2  →  조각 5개

ropes = [10, 7]을 L = 2로 자르면 조각은 몇 개일까?

10 // 2 = 5와 7 // 2 = 3을 더한 8개이다.

범위 줄이기 (선택)

후보 길이의 범위 [lo, hi]를 절반씩 줄여 가장 긴 L을 찾는다. ⑱은 mid 길이로 잘랐을 때 조각이 충분한지 묻는 조건이고, ⑲는 그렇지 않을 때 hi의 새 값이다. 채운 뒤 [▶ 실행]과 [✔ 점검]을 누른다.

점검이 낸 가장 긴 L과 호출 횟수는 활동지 3부 A14의 [코드 결과] 칸에 쓴다.

점검이 끝난 뒤 내 결과를 눈으로 대조하고 싶으면 아래 상자를 연다.

활동을 마친 뒤 열어 확인한다 · TA 점검 기대값

TA = [2, 2, 2, 6, 6, 10, 14, 14, 14, 14, 18]에서 손으로 구한 값이다. 점검 코드는 이 값을 따로 쓰지 않고 하나씩 세어 비교하므로, 내 결과를 눈으로 대조할 때 쓴다.

함수호출 → 값
count_equal(TA, 2) → 3 · (TA, 6) → 2 · (TA, 14) → 4 · (TA, 18) → 1 · (TA, 8) → 0 · (TA, 0) → 0 · (TA, 99) → 0 · ([], x) → 0
count_in_range (양끝 포함)(TA, 3, 14) → 7 · (TA, 2, 2) → 3 · (TA, 6, 6) → 2 · (TA, 7, 9) → 0 · (TA, 0, 100) → 11 · (TA, 19, 30) → 0 · (TA, -5, 1) → 0 · (TA, 14, 6) → 0 · ([], lo, hi) → 0
closest_value (동률이면 작은 값)(TA, 0) → 2 · (TA, 2) → 2 · (TA, 4) → 2 · (TA, 8) → 6 · (TA, 12) → 10 · (TA, 16) → 14 · (TA, 20) → 18 · (TA, 99) → 18 · (TA, 6) → 6 · (TA, 10) → 10 · ([], x) → None

closest_value(TA, 4)는 2와 6이 같은 거리이므로 작은 값 2이다. 입력 리스트를 정렬하거나 바꾸면 “입력 불변” 점검에서 걸린다.
