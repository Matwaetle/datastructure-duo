이론 정리 · 배경 지식

이번 주 성취기준은 [12자구04-02]예요. 정렬된 데이터에서 bisect 모듈로 Lower/Upper Bound를 써서 빠르게 탐색하는 거예요. 이 상자에는 활동에 필요한 낱말, 문법, 표기만 모아 두었어요. 탐구로 알아낼 내용은 활동 뒤 초록색 확인 상자와 마지막 학습지(3부) 끝의 정리 상자에 있어요.

1. 낱말

  • 탐색 · 정렬: 탐색은 원하는 값의 자리를 찾거나, 없다는 걸 확인하는 일이에요. 정렬은 값을 크기 순서로 줄 세우는 일이에요(오름차순은 작은 것부터). 같은 값이 여러 개 있어도 돼요. 예: [3, 8, 8, 15, 21].
  • 인덱스: 원소의 자리 번호예요. 맨 앞이 0번이고, 길이가 N이면 마지막은 N-1번이에요.
  • 비교 1회: 목표 값과 후보 하나를 비교해서 같은지, 큰지, 작은지 알아보는 일 한 번이에요. 알고리즘이 얼마나 빠른지는 이 횟수로 가늠해요.
  • 분할 정복: 문제를 같은 모양의 더 작은 문제로 나누어 풀고, 결과를 합치는 방법이에요. 재귀(8주차)로 쓰는 경우가 많아요.
  • 병합(merge): 이미 정렬된 두 리스트를 하나의 정렬된 리스트로 합치는 일이에요. 두 리스트의 맨 앞끼리 비교해서 작은 것을 하나씩 꺼내 붙여요.
  • 피벗(pivot): 나머지 원소를 “피벗보다 작은 쪽 / 큰 쪽”으로 나누는 기준 원소예요.
  • Lower Bound / Upper Bound: 정렬된 리스트에 값 x를 넣어도 정렬이 유지되는 자리의 경계예요. Lower Bound는 x 이상인 값이 처음 나오는 인덱스예요. Upper Bound는 x보다 큰 값이 처음 나오는 인덱스예요. 그런 값이 없으면 리스트의 길이가 돼요.

2. 파이썬 문법과 표준 라이브러리

# 이론 정리 예: 작은 리스트로 문법 확인
a = [3, 8, 8, 15, 21]            # 오름차순, 같은 값 8이 둘
print(a.index(8))                # 1  (처음 나오는 8의 인덱스)
print(8 in a, 9 in a)            # True False  (in: 있는지)
print(sorted([5, 2, 9, 2]))      # [2, 2, 5, 9]  (정렬된 새 리스트)
print(7 // 2, 10 // 3)           # 3 3  (//: 나눗셈의 몫만 남긴다)

import bisect                    # 정렬된 리스트용 표준 라이브러리
print(bisect.bisect_left(a, 8))  # 1  (Lower Bound)
print(bisect.bisect_right(a, 8)) # 3  (Upper Bound)
  • list.sort()는 그 리스트를 제자리에서 정렬해요. sorted(리스트)는 원래 리스트는 그대로 두고 새 리스트를 돌려줘요.
  • bisect_left(a, x), bisect_right(a, x)는 정렬된 리스트 a에서 각각 Lower Bound, Upper Bound 인덱스를 돌려줘요. 값을 바꾸거나 넣지는 않아요.
  • 함수는 def 이름(매개변수):로 정의하고 return으로 값을 돌려줘요. 재귀는 함수가 자기 자신을 부르는 거예요.

3. 복잡도 표기 읽는 법

  • N은 입력 원소 수예요. O( )는 N이 커질 때 비용이 대략 어떤 모양으로 늘어나는지 나타내요. 상수배와 작은 항은 무시해요. 예: 3N + 5는 O(N)이에요. O(N)은 N에 비례해 늘어요. O(N²)은 N이 10배가 되면 100배가 돼요.
  • log₂ N은 “2를 몇 번 곱해야 N이 되는가”예요. 예: 2³ = 8이니까 log₂ 8 = 3이에요. 보통 밑 2는 빼고 O(log N)으로 써요. O(N log N)은 N에 log N을 곱한 모양이에요.
  • 최악의 경우는 운이 가장 나쁜 입력을 만났을 때 드는 비용이에요. 평균은 보통 입력에서 드는 비용이고요. 같은 알고리즘이라도 둘이 다를 수 있어요.

지난주 BFS는 “가까운 곳부터 한 겹씩” 살폈어요. 이번 주는 “가운데부터 절반씩” 줄여 갈 수 있는지 살펴봐요. 1차시(A1~A6)에는 탐색과 정렬을 손으로 따라 해 봐요.

A1 · 몇 번 만에 찾을까1차시 · 6분 · 개인

정렬된 데이터에서 원하는 값을 몇 번 만에 찾을 수 있을까요? 작은 숫자 맞히기 게임으로 시작해 봐요.

숫자 맞히기 게임

컴퓨터가 1~8 중 수 하나를 정했어요. 내가 수를 말하면, 정답이 더 큰지 작은지만 알려 줘요.

정답이 6일 때
말한 수   컴퓨터의 답
  4       더 크다
  7       더 작다
  6       맞다

4를 말했더니 ‘더 크다’를 들었어요. 정답이 될 수 있는 수는?

5~8이에요. 말한 4와 그보다 작은 수는 후보에서 빠져요.

이어서 7을 말했더니 ‘더 작다’를 들었어요. 남은 후보는?

5와 6이에요. 말할 때마다 후보가 줄었어요. 8개에서 2개가 됐어요.

1~100에서는 몇 번?

같은 놀이를 1~100으로 해 봐요. 운이 가장 나쁠 때도 반드시 맞히려면, 수를 최대 몇 번 말해야 할까요? 맞히는 마지막 말도 1번으로 세요. 최대 횟수와 수를 고르는 방법을 써요.

사전에서 찾기

가나다 순으로 실린 국어사전에서 ‘탐구’를 찾아요. 처음에 어디를 펴는지 써요. 펼친 쪽이 ‘탐구’보다 뒤였다면, 다음에 어느 쪽을 펴는지도 써요.

10억 개에서는?

작은 값부터 놓인 학번 10억 개에서 학번 하나를 찾아요. 하나씩 보면 최대 몇 번일까요? 내가 생각한 방법으로는 몇 번쯤일까요? 자릿수만 맞으면 돼요.

3하나씩 보면 최대 번, 지금 생각한 방법으로 하면 번쯤

여기까지 세 사례에서 찾는 방법과 횟수를 어림해 봤어요. A2에서는 이 규칙을 정확히 약속하고 손으로 따라 해 봐요.

다 쓰고 나서 열어 봐요 · 세 사례의 어림값과 공통점
  • 사전: 가운데쯤을 펴 봐요. 목표가 앞쪽이면 앞쪽 절반만, 뒤쪽이면 뒤쪽 절반만 다시 펴요.
  • 숫자 맞히기: 50을 불러요. “높다/낮다”에 따라 남은 후보의 가운데를 부르면, 최악이어도 7번이면 맞혀요(27 = 128 ≥ 100).
  • 학번 10억 개: 하나씩 보면 최대 10억 번이에요. 한 번 비교할 때마다 후보를 절반쯤 버리면 30번 안팎이에요(230 ≈ 10.7억).
  • 세 사례의 공통점은 한 번 비교할 때마다 후보를 크게 줄인다는 거예요. 내 규칙이 이와 달라도 괜찮아요. A2에서 규칙을 정확히 약속하고 손으로 따라 해 봐요.

A2 · 후보 범위를 가운데에서 줄이기1차시 · 11분 · 개인

찾는 규칙을 약속해 봐요.

작은 배열로 규칙 익히기

아직 답이 있을 수 있는 구간을 [lo, hi]로 써요.

규칙  ① 처음에는 lo = 0, hi = 마지막 인덱스.
      ② mid = (lo + hi) // 2 (// 는 몫만 남김)의 값 a[mid]와 목표를 견준다(비교 1회).
      ③ 같으면 끝. 크면 lo = mid + 1, 작으면 hi = mid - 1.
      ④ lo > hi 가 되면 ‘없음’으로 끝낸다.

a = [3, 7, 9, 14, 20]     인덱스 0 1 2 3 4     목표 14
단계  lo  hi  mid  a[mid]  판정
 1     0   4    2     9    14 > 9 → lo 이동, lo = 3

2단계의 mid는 몇 번 칸일까? (lo = 3, hi = 4)

(3 + 4) // 2 = 3이에요. a[3] = 14라서 같음이고, 비교 2회에 끝나요.

같은 배열에서 목표가 3이면, 1단계 판정은?

3 < 9이니까 mid와 그 오른쪽을 버려요. hi = mid - 1 = 1이 돼요.

비교 횟수 세기

규칙대로 찾을 때와 맨 앞부터 하나씩 비교할 때의 비교 횟수를 세요. 하나씩 비교할 때는 찾으면 멈추고, 없으면 끝까지 비교해요.

목표규칙대로(비교 횟수)맨 앞부터 하나씩(비교 횟수)

40

왜 그럴까?

표를 보며 답해 봐요.

a[mid]가 23보다 작으면 mid와 그 왼쪽을 버려요. 왼쪽을 더 볼 필요가 없는 이유는?

40이 없다고 결론 내리는 때는 언제일까요?

한 번 비교할 때마다 후보가 절반으로 준다고 해 봐요. 1000개를 1개가 남을 때까지 줄여 써요(1000 → 500 → …). 마지막 1개를 비교하는 1회를 더해서 세요. 1000개와 100만 개일 때 규칙의 최대 비교 횟수는 몇 번쯤일까요? 하나씩 비교하면 같은 경우 몇 번일까요?

여기까지 후보 범위를 가운데에서 줄이는 규칙으로 23과 40을 찾았어요. A3에서는 같은 규칙을 다른 배열에 써 봐요.

다 쓰고 나서 열어 봐요 · 추적표 값과 줄어드는 속도

목표 23의 후보 범위가 줄어드는 모습이에요. 값이 적힌 칸이 후보 범위고, 빈칸은 버린 범위예요.

s2                         23  38  56  72  91   mid=7 값 56, 23 < 56 이므로 hi=6
s3                         23  38               mid=5 값 23, 같음

  • 질문 1: a[mid]가 23보다 작으면, mid와 그 왼쪽 원소는 모두 a[mid] 이하예요. 목표 23은 더 크니까 오른쪽에만 있을 수 있어요. 그래서 왼쪽을 버려요.
  • 질문 2: 후보 범위가 비었을 때(lo > hi)예요. 즉 마지막으로 38과 비교한 직후에 알게 돼요.
  • 질문 3: 1000개를 1개가 될 때까지 줄이는 데 9번이 들고, 마지막 1개를 비교하는 1번을 더해 10번이에요(100만 개는 19 + 1 = 20번). 한 번 비교할 때마다 후보가 절반이 되니까, 최대 비교 횟수는 원소 10개에서 4, 1000개에서 10, 100만 개에서 20, 10억 개에서 30번 안팎이에요. 하나씩 비교하면 같은 경우에 최대 N번이에요. 원소가 10배가 되면 하나씩은 약 10배로 늘지만, 절반 버리기는 3~4번 늘 뿐이에요.

왜 놓쳤을까?

23은 UNS에 있는데 규칙은 “없음”이라고 했어요. 추적표를 보며 어느 단계부터 어긋났는지 찾아요. 그리고 서로 다른 원인 후보 2가지를 써요. 후보는 결론이 아니라 ‘그럴 수 있다’는 짐작이에요.

여기까지 같은 규칙이 UNS에서는 23과 56을 놓쳤어요. A4에서는 8개를 줄 세우는 두 방식을 손으로 따라 해 봐요.

깊이 세는 법

깊이는 재귀 호출이 겹쳐 들어간 가장 깊은 단계의 수예요. 처음 호출이 1단계예요. 길이 0이나 1에서 멈추는 호출도 한 단계로 세요. 가운데 피벗은 a[len(a)//2]예요. 이 예는 가운데 피벗으로 해도 비교 합 3회, 깊이 3이에요.

[3, 1, 2]  첫 원소 피벗 3 → 작은 쪽 [1, 2], 큰 쪽 [ ]   비교 2회
          [1, 2]는 피벗 1 → [ ]와 [2]               비교 1회
          비교 합 3회, 깊이 3
          가운데 피벗이면 a[1] = 1 → 작은 쪽 [ ], 큰 쪽 [3, 2]  (이어서 비교 합 3회, 깊이 3)

[4, 5]를 첫 원소 피벗으로 가르면 깊이는?

[4, 5]가 1단계, 갈라진 [ ]와 [5]가 2단계예요.

방식 가로 4개를 합칠 때 합치는 층은 몇 층일까요? (1개씩 → 2개씩 → 4개로)

1개씩 → 2개씩 → 4개로, 합치는 층은 두 층이에요.
